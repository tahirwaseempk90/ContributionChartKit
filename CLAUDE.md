# 7. Architecture and Engineering Principles

Design this framework as a senior iOS architect.

Follow the principles below.

## SOLID

### Single Responsibility Principle
Every type should have one clear responsibility.

Examples:
- Data models represent chart data.
- Configuration models represent chart settings.
- Scale calculator calculates numeric scaling.
- Layout engine calculates geometry.
- Renderer draws chart elements.
- Accessibility layer describes chart content.

Avoid classes or structs that perform unrelated responsibilities.

### Open/Closed Principle
The package should support new chart customization and extension without constantly modifying existing core implementation.

### Liskov Substitution Principle
Where protocols and abstraction hierarchies are introduced, implementations must remain behaviorally compatible.

Do not create inheritance hierarchies unnecessarily.

### Interface Segregation Principle
Keep public protocols focused and minimal.

Do not expose unnecessarily large interfaces.

### Dependency Inversion Principle
Keep the rendering and layout calculations independent of application-specific data sources and business logic.

## Additional Principles

Follow:
- Clean Architecture.
- Separation of Concerns.
- DRY.
- KISS.
- YAGNI.
- Composition over inheritance.
- Immutability where appropriate.
- Protocol-oriented design where beneficial.
- Explicit access control.
- Dependency injection where needed.
- Value semantics where appropriate.

Do not overengineer a chart component with unnecessary ViewModels, coordinators, repositories, factories, or managers.

Every abstraction must have a clear reason to exist.

# 9. Public API Design

The package must expose a simple and intuitive API.

A consuming developer should be able to integrate the chart with minimal code.

Example:

```swift
import SwiftUI
import ContributionChart

struct PortfolioView: View {

    private let data: [ChartDataPoint] = [
        .init(title: "VFIAX", value: 11.05),
        .init(title: "VTNIX", value: 6.31),
        .init(title: "VTSAX", value: -2.70)
    ]

    var body: some View {
        ContributionChart(points: data)
            .frame(maxWidth: .infinity)
            .frame(height: 260)

}
```

- Optional baseline.

- Empty state customization.
- Accessibility configuration.
- Future extensibility.

Keep the basic integration simple.

Advanced configuration should remain optional.

Avoid exposing internal rendering implementation details.

Review every public API before finalizing it.
